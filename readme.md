## Домашнее задание. Знакомство с Django в рамках обучения по специальности "Разработчик Python" университета Skypro.  

**Задачи выполняемые программой:**  
Отработка темы "Кэширование и бизнес логика" в Django:  
 - Redis как брокер для кеширования;  
 - Вынос бизнес логики в сервисную функцию;  
 - Кэширование страницы и низкоуровневое кэширование.  

**Для пользователей:** 
Запуск сервера: `python manage.py runserver`, в браузере открыть страницу http://127.0.0.1:8000

**Для разработчиков:**  
Установка:  
 - скачать дистрибутив с python.org и установить Python;  
 - скачать и установить PostgreSQL, создать пользователя с правами владельца базы данных.
Предупреждение:  
❌ Не давайте пользователю SUPERUSER (это администратор всей СУБД);  
❌ Не используйте пользователя postgres (суперпользователь по умолчанию) для Django;  
❌ Не храните пароль в коде (используйте .env);  
 - после выполнения миграций загрузить фикстуры:`python auxiliary/load_fixtures.py`. Порядок загрузки важен и в данном случае определён
	словаврём FIXTURE_DICT в auxiliary/constants.py(см.ниже), поэтому в случае загрузки иным способом первой необходимо загрузить фикстуру first_load_users_groups.json;

**Состав программы:**  
- manage.py - точка входа;  
- requirements.txt - файл списка зависимостей и версий;  
- site_22/ - директория проекта;  
- hub/ - директория приложения hub - стартовой страницы с ссылками на приложения проекта;  
- contacts/ - директория приложения Контакты;  
- catalog/ - директория приложения Каталог;  
- blog/ - директория приложения Блог;  
- templates/ - директория шаблонов общих для проекта;  
- fixtures/ - директория расположения фикстур;  
- auxiliary/ - директория вспомогательных модулей;  
- auxiliary/constants.py - константы проекта;  
- auxiliary/make_fixtures.py - создание-выгрузка фикстур автоматически;  
- auxiliary/load_fixtures.py - загрузка фикстур. Загрузка и выгрузка фикстур производится в соответствии с FIXTURE_DICT из constants.py;  
- auxiliary/utils.py - модуль вспомогательных функций;  
- auxiliary/refill_data.py - повторное заполнение БД.  


## Особенности  
- Проект содержит приложения: hub(hub/) - стартовая страница с ссылками на приложения проекта, Каталог(catalog/) - веб магазин, Блог(blog/) - собственно блог, Контакты(contacts/) - контакты;  
- При достижении 100 просмотров поста автор получает email-уведомление (в консоль при `DEBUG=True`);  
- При значении `DEBUG=False` в случае ошибочного адреса страницы обоих приложений отрабатывается кастомная общая страница 404;
